AI VOICE ASSISTANT (JARVIS) - PROJECT STUDY REPORT
==================================================

Report ka maqsad
---------------
Yeh report repository ke maujooda source code, requirements.txt, data/knowledge.txt,
frontend aur README ko padh kar banayi gayi hai. Iska use project ko samajhne,
seekhne, aur apna AI voice agent banane ke reference ke roop mein kiya ja sakta hai.

Important: README mein kai features future/desired project ke roop mein likhe hain.
Neeche "abhi implemented" aur "abhi nahi / incomplete" ko alag bataya gaya hai.
Yeh source-code inspection par aadharit report hai; application ko run karke
end-to-end test nahi kiya gaya.


1. PROJECT KA OVERVIEW
----------------------
Yeh Python-based Jarvis-style assistant hai jisme:

- Streamlit chat UI aur microphone recording deta hai.
- FastAPI backend text chat aur audio-upload endpoints deta hai.
- Ollama par chalne wala Llama 3 model jawab banata hai.
- LangChain aur ChromaDB ke zariye local knowledge-base se RAG retrieval hota hai.
- Hugging Face sentence-transformer text ko embeddings mein badalta hai.
- Whisper uploaded audio ko text mein transcribe karta hai.
- gTTS frontend mein assistant response ko MP3 speech mein badalta hai.
- Google, YouTube, Weather search aur Maps ke liye browser tabs kholne wale
  helper functions hain.
- Ek alag command-line voice loop SpeechRecognition aur pyttsx3 ka istemal karta hai.

High-level architecture:

User (text ya microphone)
    -> Streamlit frontend (frontend/streamlit_app.py)
    -> FastAPI backend (app/main.py)
    -> command routing ya RAG (app/tools.py / app/rag.py)
    -> Ollama LLM + ChromaDB/Hugging Face embeddings
    -> answer wapas frontend ko
    -> gTTS se browser mein audio playback

Voice API path:

Microphone recording
    -> Streamlit audio upload
    -> FastAPI /voice
    -> Whisper transcription
    -> RAG answer
    -> Streamlit response + gTTS playback


2. TECH STACK AUR USKA KAAM
----------------------------

Python
  Backend, voice logic, RAG pipeline aur Streamlit UI Python mein likhe gaye hain.
  README prompt Python 3.11+ ka zikr karta hai, lekin requirements.txt mein
  Python version pin ya project configuration maujood nahi hai.

FastAPI
  app/main.py mein HTTP backend hai. POST /chat JSON question/history leta hai.
  POST /voice multipart audio file leta hai. FastAPI app ko Uvicorn serve karta hai.

Pydantic
  ChatRequest model /chat request body ke question aur history fields ko define
  karta hai. History filhaal plain list hai; har message ka strict schema define
  nahi hai.

Streamlit
  frontend/streamlit_app.py chat screen, sidebar, chat state, recording control,
  API calls, errors aur audio output sambhalta hai.

Custom CSS
  frontend/styles.css dark gradient background, header, card, sidebar aur audio/
  chat input styling deta hai. Kuch message bubble styling CSS mein hai, jabki
  messages ka HTML Python file mein inline banaya gaya hai.

LangChain
  Ollama LLM aur Chroma vector store ko jodne ke liye prayog hua hai.
  app/rag.py mein OllamaLLM aur retriever invoke hote hain.

Ollama + Llama 3
  app/rag.py llama3 model ko temperature 0.3 ke saath configure karta hai.
  Iske liye Ollama machine par chalna chahiye aur llama3 model available hona chahiye.

ChromaDB
  Persistent vector database db/ directory mein configure hai. app/vectorstore.py
  Chroma collection ko disk par rakhta/kholega.

Hugging Face sentence-transformers
  all-MiniLM-L6-v2 model knowledge text aur user query ke embeddings ke liye
  configure kiya gaya hai. Pehli baar model download/cache ho sakta hai.

Whisper
  app/main.py import ke samay Whisper ka "base" model load karta hai.
  /voice endpoint uploaded audio ko transcribe karne ke liye model.transcribe()
  chalata hai. Whisper package requirements.txt mein listed nahi hai.

SpeechRecognition
  app/app.py ke command-line loop mein microphone input aur recognize_google()
  speech-to-text ke liye hain. Is path ko internet aur system microphone/audio
  dependencies ki zaroorat pad sakti hai.

gTTS
  frontend/streamlit_app.py assistant text ka MP3 audio banata hai aur HTML audio
  player ke zariye browser mein play karta hai. gTTS requirements.txt mein listed
  nahi hai. gTTS aam taur par Google text-to-speech service tak network request
  karta hai.

pyttsx3
  app/app.py aur app/speech.py/app/tts.py mein local text-to-speech ke liye use
  hua hai. Yeh Streamlit UI ka output path nahi hai; CLI voice loop mein pyttsx3
  bolta hai.

requests
  Streamlit frontend FastAPI ko HTTP requests bhejta hai. requirements.txt mein
  requests listed nahi hai.

streamlit-mic-recorder
  Frontend microphone widget is external package se aata hai. Yeh
  requirements.txt mein listed nahi hai.

urllib.parse, re, webbrowser
  Standard-library modules. Search query encode karne, command text saaf karne,
  aur backend host par browser tab kholne mein app/tools.py inka use karta hai.


3. REPOSITORY FILES KA ROLE
---------------------------

app/main.py
  FastAPI backend. Chat command routing, /chat endpoint, /voice upload endpoint,
  Whisper model loading aur audio transcription.

app/rag.py
  Chroma retriever (top 3 results), Ollama LLM, system prompt aur answer
  generation. Chat history ke aakhri 10 messages prompt mein bheje jaate hain.

app/vectorstore.py
  Hugging Face embedding model aur db/ mein persistent Chroma store banata/kholega.

app/ingest.py
  data/knowledge.txt ko ek LangChain Document mein padhta hai aur vector store mein
  add karta hai. Yeh script ingestion ke liye chalayi ja sakti hai.

app/tools.py
  YouTube, Google, weather aur Google Maps search URL banata hai aur
  webbrowser.open_new_tab() se kholta hai. Weather function real weather API se
  data nahi laata; yeh Google search results page kholta hai.

app/app.py
  Independent command-line microphone assistant: SpeechRecognition se sunta hai,
  recognize_google() se text banata hai, ask_rag() se answer leta hai, aur
  pyttsx3 se bolta hai. "exit", "quit", "stop" par rukta hai.

app/speech.py aur app/tts.py
  Dono pyttsx3 ke engine ko initialize karke speak(text) function dete hain.
  Maujooda frontend/backend path in functions ko use nahi karta.

app/test_tts.py
  Automated test suite nahi, balki ek ad-hoc experiment hai: gTTS MP3 banata hai,
  phir "afplay" se chalane ki koshish karta hai, aur LangChain @tool weather
  example chalata hai. "afplay" macOS command hai; Windows par yeh test seedha
  kaam nahi karega.

frontend/streamlit_app.py
  Streamlit UI, mic_recorder, session_state chat messages, FastAPI requests aur
  gTTS autoplay audio.

frontend/styles.css
  Streamlit UI ke visual styles.

data/knowledge.txt
  Abhi chhota sample knowledge corpus: Python, FastAPI, Django, RAG aur Ollama
  ke baare mein 5 lines.

db/
  Chroma database files. Is data ko source code samajh kar edit nahi karna chahiye.

requirements.txt
  Python packages: FastAPI, Uvicorn, Streamlit, LangChain integrations, ChromaDB,
  sentence-transformers, pyttsx3, SpeechRecognition aur python-multipart.

readme
  Ismein run commands ke saath ek bada project-generation prompt/specification hai.
  Prompt ke har requested feature ko current code mein implemented na samjhein.

temp.wav
  Root mein audio file maujood hai; /voice endpoint bhi isi naam se current working
  directory mein upload likhta hai. Isliye running request is file ko overwrite
  kar sakti hai.

5. REQUEST FLOW - PEHLE STEP SE AAKHIRI STEP TAK
-------------------------------------------------

A. Text chat ka flow

1. User Streamlit chat box mein text likhta hai.
   Check: UI khulni chahiye aur input box dikhna chahiye.

2. Frontend session messages ke saath question ko POST /chat par bhejta hai.
   Check: backend chal raha ho; browser/network response mein HTTP 200 aur JSON
   mein "answer" field aaye.

3. Backend question lower-case karke intent dekhta hai. Pehle YouTube, phir
   Google open, weather, maps, Google search; match na ho to RAG.
   Check: "open youtube", "weather in Bangalore", "open maps Mysore" aur ek normal
   knowledge question alag-alag bhejkar response/route dekhein.

4. RAG query par Chroma retriever adhiktam 3 relevant documents dhoondhta hai.
   Check: pehle ingest complete ho; query knowledge.txt ke maujood facts se judi
   ho aur retrieved source relevant ho.

5. Recent history + retrieved text + system prompt Ollama Llama 3 ko diya jaata
   hai; model response deta hai.
   Check: Ollama service/model available ho; /chat mein answer non-empty ho.
   Follow-up test: "My name is Asha" ke baad "What is my name?" bhejein. UI ki
   history forwarding ko test karein; ise permanent memory na samjhein.

6. Frontend user aur assistant messages session_state mein add karta hai.
   Check: rerun ke baad dono messages chat mein bane rahein; Clear Chat dabane par
   current UI conversation clear ho.

7. Frontend gTTS se answer ka MP3 banata hai aur browser mein autoplay audio deta hai.
   Check: network available ho, gTTS request fail na ho, browser audio autoplay
   allow kare. Browser autoplay policy ke karan manual play ki zaroorat ho sakti hai.

B. Voice upload ka flow

1. Streamlit mic_recorder se audio record karein.
   Check: microphone permission, input device aur recorder widget kaam karein.

2. Frontend recorded bytes ko multipart "file" ke roop mein POST /voice bhejta hai.
   Check: network request mein audio/wav metadata aur audio bytes hon.

3. Backend temp.wav mein file likhkar Whisper base model se transcribe karta hai.
   Check: /voice response mein pehchana gaya "question" text hona chahiye. Noisy
   audio, silence aur English/Hindi mix ko alag cases mein check karein.

4. Transcribed text seedha ask_rag() ko jaata hai.
   Check: voice se normal knowledge question bolkar response dekhein. Dhyan rahe:
   filhaal voice route chat history aur /chat ke browser command routing ko reuse
   nahi karta.

5. Frontend answer chat mein dikhata hai aur gTTS audio play karta hai.
   Check: transcription, answer aur playback teeno independently confirm karein.

C. Knowledge ingestion aur RAG setup

1. data/knowledge.txt mein apne domain ke saaf, sahi facts add karein.
   Check: file encoding readable ho; content mein headings/paragraphs useful hon.

2. Chroma aur embedding dependencies install hon; Hugging Face embedding model
   pehli baar download/cache ho sakta hai.
   Check: model load aur Chroma initialization bina error ke ho.

3. Repository root se `python -m app.ingest` chalayein.
   Check: "Knowledge Base Loaded" aaye. Phir us content se related /chat query karein.

4. Database persistence verify karein: backend restart karke wahi query karein.
   Check: knowledge dobara ingest kiye bina retrieval rahe. Ingestion baar-baar
   chalane par duplicate documents ban sakte hain, kyunki stable IDs/dedup logic
   nahi dikh raha.

10. SHORT GLOSSARY
------------------
LLM: Bada language model jo natural language response generate karta hai.
RAG: Pehle relevant documents retrieve, phir un context se LLM response generate.
Embedding: Text ka numerical representation jo semantic similarity dhoondhne mein
kaam aata hai.
Vector store: Embeddings aur unse judi text/document entries ka searchable store.
STT: Speech-to-Text; audio se likha hua text banana.
TTS: Text-to-Speech; likhe text ko audio mein badalna.
API endpoint: Backend ka HTTP address, jaise POST /chat.
Session state: Is Streamlit session ke dauran rakha temporary UI data; permanent
database memory ke barabar nahi.

  import os
  from dotenv import load_dotenv

  load_dotenv()

  LLM_PROVIDER = os.getenv("LLM_PROVIDER", "gemini").strip().lower()
  GEMINI_API_KEY = os.getenv("GEMINI_API_KEY")
  GEMINI_MODEL = os.getenv("GEMINI_MODEL", "gemini-2.5-flash")
  OPENAI_API_KEY = os.getenv("OPENAI_API_KEY")
  OPENAI_MODEL = os.getenv("OPENAI_MODEL", "gpt-4.1-mini")

  def validate_llm_config() -> None:

          raise RuntimeError("GEMINI_API_KEY is required when LLM_PROVIDER=gemini")
      if LLM_PROVIDER == "openai" and not OPENAI_API_KEY:
          raise RuntimeError("OPENAI_API_KEY is required when LLM_PROVIDER=openai")
      if LLM_PROVIDER not in {"gemini", "openai"}:
          raise RuntimeError("LLM_PROVIDER must be 'gemini' or 'openai'")

D. app/llm.py - provider calls ka example

  from functools import lru_cache
  from google import genai
  from openai import OpenAI
  from app.config import (
      GEMINI_API_KEY, GEMINI_MODEL, LLM_PROVIDER,
      OPENAI_API_KEY, OPENAI_MODEL, validate_llm_config,
  )

  @lru_cache(maxsize=1)
  def _gemini_client() -> genai.Client:
      validate_llm_config()
      if not GEMINI_API_KEY:
          raise RuntimeError("GEMINI_API_KEY is required")
      return genai.Client(api_key=GEMINI_API_KEY)

  @lru_cache(maxsize=1)
  def _openai_client() -> OpenAI:
      validate_llm_config()
      if not OPENAI_API_KEY:
          raise RuntimeError("OPENAI_API_KEY is required")
      return OpenAI(api_key=OPENAI_API_KEY)

  def generate_text(prompt: str) -> str:
      if LLM_PROVIDER == "gemini":
          response = _gemini_client().models.generate_content(
              model=GEMINI_MODEL,
              contents=prompt,
          )
          text = response.text
      elif LLM_PROVIDER == "openai":
          response = _openai_client().responses.create(
              model=OPENAI_MODEL,
              input=prompt,
          )
          text = response.output_text
      else:
          validate_llm_config()
          raise RuntimeError("Unsupported LLM provider")
      if not text or not text.strip():
          raise RuntimeError(f"{LLM_PROVIDER} returned an empty response")
      return text.strip()
